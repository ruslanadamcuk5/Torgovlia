# Аудит безопасности и изоляции арендаторов

Дата: ноябрь 2026. Область: backend API, tenant-контекст, админка магазина,
платформа, загрузка файлов, журнал действий. Задача 10.2.

## Метод

1. Просмотр `app/tenancy.py`: как middleware определяет tenant, как
   `with_loader_criteria` фильтрует выборки и как `before_flush` проставляет
   `tenant_id`.
2. Поиск всех `select(...)`, `db.get(...)` и `execution_options(skip_tenant_filter=True)`.
3. Проверка доступа по чужому ID для ключевых сущностей.
4. Проверка входа: токен магазина на чужом Host, токен платформы на маршрутах
   магазина, заголовок `X-Tenant-Slug` в production.
5. Проверка загрузки и выдачи файлов, журнала действий, демо-режима.

Автотесты: `backend/tests/test_isolation.py`, `backend/tests/test_platform.py`,
`backend/tests/test_signup.py`.

## Что проверено

| Область | Результат |
|---|---|
| Товары, категории, настройки | список и доступ по ID фильтруются; чужая запись → 404 |
| Заказы и поиск по номеру | чужой заказ по ID и по номеру+телефону недоступен |
| Клиенты, заметки, метки | карточка чужого клиента → 404; заметки и метки не видны |
| Подарочные сертификаты | чужой код → 404; список и изменение по ID недоступны |
| Регулярные заказы | чужой ID → 404; список не содержит чужих |
| Задачи сотрудников | чужой ID и чужой исполнитель отклоняются |
| Журнал действий | **найдена утечка**: отдавался журнал всех арендаторов; исправлено фильтром по `tenant_id` |
| Загрузка файлов | файлы раскладываются по `uploads/<slug>/`; имена случайные; формат проверяется по исходному формату изображения |
| Вход магазина | токен магазина A на Host магазина B → 401 |
| Платформа | маршруты `/api/platform/*` требуют отдельный токен платформы |
| `X-Tenant-Slug` | разрешён только в `DEMO_MODE` или не-production; в production выключен |
| Демо | сброс каждые 24 часа; демо-пароли нужно менять перед продакшеном |

## Найденные и исправленные дефекты

1. **Журнал действий отдавал данные всех магазинов.** `GET /api/admin/audit`
   выбирал `AuditLog` без фильтра. `AuditLog` не входит в `TenantMixin`, поэтому
   автофильтр не применялся. Исправлено явным `WHERE tenant_id = current`.
2. **Загрузка изображений могла отклонять валидные файлы.** После
   `Image.load()` Pillow очищает `image.format`, поэтому проверка формата
   срабатывала ложно. Формат теперь запоминается до преобразований.
3. **Медиа не были разложены по арендаторам.** Новые файлы пишутся в
   `uploads/<slug>/`, что упрощает удаление данных при расторжении договора и
   выборочный бэкап.

## Остаточные риски и решения

| Риск | Уровень | Мера |
|---|---|---|
| Нет PostgreSQL RLS: изоляция держится на коде | средний | тесты IDOR, код-ревью, позже RLS для критичных таблиц |
| JWT живёт 7 дней | средний | короткий срок для админов, отзыв при смене пароля, HTTPS |
| Rate limit входа хранится в памяти процесса | низкий | при нескольких воркерах вынести в Redis/nginx |
| Публичные медиа доступны по прямой ссылке | низкий | случайные имена; для приватных документов — отдельное хранилище с авторизацией |
| Демо-пароли `ChangeMe123!` | высокий до смены | чек-лист запуска, `SEED_DEMO=false` в production |
| Telegram/SMTP могут получить персональные данные | средний | отправлять только служебные события, см. PD-аудит |
| Бэкапы лежат рядом с сервером | высокий | выгрузка во внешнее хранилище, шифрование, проверка восстановления |
| Нет WAF/защиты от DDoS на shared-хостинге | средний | nginx-лимиты, внешний мониторинг, VPS при росте |
