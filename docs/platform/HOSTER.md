# Интеграция с hoster.by

Дата исследования: **06.11.2026**. Источники: публичные страницы hoster.by,
партнёрская программа, страницы хостинга, тарифы, личный кабинет `cp.hoster.by`,
документация ispmanager.

## 1. Краткий вывод

**Публичного API для покупки домена, хостинга и управления биллингом у hoster.by
не обнаружено.** Партнёрская программа существует, но заявки и передача проектов
идут через личный кабинет и менеджера, а не через документированный API.

Что это значит:

- полностью автоматизировать «выбор домена → оплата → регистрация → хостинг →
  деплой» **только средствами публичного API hoster.by сейчас нельзя**;
- автоматизацию нужно строить слоями: свой биллинг и провижининг + адаптеры,
  где часть шагов выполняется вручную или через ispmanager;
- нужно отправить официальный запрос в hoster.by о партнёрском/реселлерском API,
  DNS API и white-label. До ответа закладываем ручной режим.

## 2. Что удалось подтвердить

### 2.1 Партнёрская программа

Страница: <https://hoster.by/partnership/>

Форматы:

| Формат | Для кого | Механика |
|---|---|---|
| Партнёрская программа | веб-студии, разработчики, агентства | рекомендуете услуги, передаёте данные проекта через кабинет, клиент платит, вы получаете вознаграждение |
| Реферальная программа | блогеры, авторы | ссылка/рекомендация, вознаграждение |
| Дилерская программа | интеграторы, комплаенс | закупка hoster Cloud по партнёрским ценам и перепродажа |
| Партнёрство по ИБ | интеграторы безопасности | индивидуальные условия, NDA |

Ключевое:

- API в условиях не упоминается;
- передача данных о проекте — через личный кабинет;
- статусы, акты и сделки отображаются в кабинете;
- для дилерской модели — предварительная консультация и индивидуальные условия.

### 2.2 Виртуальный хостинг

Страница: <https://hoster.by/service/hosting/unix/>

| Тариф | Цена, BYN/мес* | Сайтов | Диск | БД | Особенности |
|---|---:|---:|---:|---|---|
| Лайт | 6,56 | 5 | 3 ГБ | есть | лендинг, витрина |
| Стандарт | 17,04 | 30 | 7 ГБ | 10 | информационный сайт, блог |
| Оптима | 20,96 | 100 | 15 ГБ | 30 | интернет-магазин |
| Профи | 34,48 | 200 | 25 ГБ | 50 | крупный проект |

\* Цена со скидкой 20% при оплате; продление — по прейскуранту.

Технически:

- панель управления — **ispmanager**;
- ОС CloudLinux, Apache + Nginx, MySQL 5.7/8.0/8.4;
- Python 3.3–3.13, Node.js до 22, Django, cron, SSH;
- бесплатный Let's Encrypt SSL с автопродлением;
- ежедневные бэкапы, хранение 30 дней;
- IPv6;
- почта на домене.

Практический вывод: приложение на FastAPI туда установить можно, но для
multi-tenant SaaS с PostgreSQL, Redis, фоновыми задачами и кастомными доменами
shared-хостинг подходит только для малого пилота. Для production нужен VPS или
облачный сервер.

### 2.3 ispmanager

- Документированный API есть у самой ispmanager: управление сайтами, БД, почтой,
  SSL, бэкапами, пользователями, cron.
- Это **API управления хостинг-аккаунтом**, а не API покупки услуг у hoster.by.
- Доступ к панели: `https://vhXXX.hoster.by:1500/ispmgr`.
- Может использоваться для:
  - создания сайта/поддомена внутри аккаунта;
  - выпуска SSL;
  - создания БД;
  - бэкапов;
  - деплоя файлов;
  - статистики.
- Не может:
  - зарегистрировать домен;
  - выставить и принять счёт;
  - купить тариф;
  - управлять биллингом.

### 2.4 Домены

- Проверка занятости: публичный WHOIS hoster.by (`https://whois.hoster.by/`) и
  RDAP для международных зон.
- Регистрация: через корзину hoster.by или партнёрский кабинет.
- DNS по умолчанию: `ns1.hoster.by`, `ns2.hoster.by`; управление DNS — в личном
  кабинете, раздела «Домены» → «Управление» → «DNS».
- Ограничение: владельцем домена в зонах `.BY`, `.БЕЛ`, `.OF.BY` может быть
  только физлицо, ИП или юрлицо (не филиал).
- Публичного API регистрации/DNS не найдено.

### 2.5 Оплата

На сайте указаны Visa, Mastercard, БЕЛКАРТ, ЕРИП, Apple Pay, UnionPay. Это оплата
услуг hoster.by, а не готовый эквайринг для платформы. Для приёма денег от
арендаторов нужен собственный договор с банком/платёжным провайдером.

### 2.6 Что не найдено

- Публичная документация `api.hoster.by` для заказа услуг.
- API биллинга, счетов, подписок.
- API регистрации доменов и управления DNS.
- White-label / реселлерский API с автоматическим созданием аккаунтов.
- Sandbox для заказа хостинга.

Отсутствие публичной документации не доказывает отсутствие API у партнёров —
нужен официальный запрос.

## 3. Рекомендуемая схема интеграции

### 3.1 Слои

```
Платформа
  ├── Billing (свой)                 → счёт, оплата, подписка
  ├── Provisioning orchestrator      → машина состояний, задачи, retries
  ├── DomainProvider
  │     ├── WhoisRdapChecker         → доступность домена (авто)
  │     ├── HosterByManualProvider   → заказ через кабинет/менеджера
  │     └── HosterByApiProvider      → если появится API
  ├── HostingProvider
  │     ├── IspManagerProvider       → аккаунт/сайт/SSL/БД
  │     ├── HosterByManualProvider   → заказ тарифа вручную
  │     └── CloudVpsProvider         → VPS/облако hoster
  └── DeploymentProvider
        ├── DockerComposeProvider    → git SHA, миграции, health
        └── SshProvider              → git pull/systemd
```

### 3.2 Режимы работы

| Режим | Что автоматизировано | Когда использовать |
|---|---|---|
| `manual` | ничего, задачи оператору + чек-лист | запуск, пилот |
| `assisted` | проверка домена, создание tenant, DNS-инструкции, деплой | первые 20–50 клиентов |
| `ispmanager` | сайт, SSL, БД, бэкап внутри аккаунта | выделенные экземпляры |
| `full` | домен + хостинг + деплой через API | если hoster.by даст API |

Режим — настройка платформы, а не код. Переключение без релиза.

### 3.3 Ручной сценарий (MVP)

1. Клиент выбирает домен и тариф на сайте платформы.
2. Платформа проверяет домен через WHOIS/RDAP.
3. Создаёт tenant, subdomain и демо-сайт.
4. Выставляет счёт; после оплаты — задача оператору.
5. Оператор в кабинете hoster.by:
   - регистрирует домен;
   - заказывает хостинг;
   - создаёт сайт;
   - выпускает SSL.
6. Вносит результат в платформу (ID услуги, логин, даты).
7. Платформа проверяет DNS/SSL и активирует сайт.
8. Клиент получает письмо и чек-лист.

Плюсы: работает сразу, без API. Минусы: ручной труд, задержка, человеческие
ошибки. Поэтому все шаги — в задачах с чек-листом и дедлайном.

### 3.4 Автоматизированный сценарий (если API появится)

1. `check_availability` → `register` → `order_id`.
2. `create_account` → `account_id`, логин, пароль.
3. `set_dns` → A/AAAA/CNAME/TXT.
4. `deploy` → контейнер/сайт, миграции, health.
5. `issue_ssl` → статус.
6. Активация и уведомление.

Все вызовы идемпотентны, с таймаутами и повторными попытками. Статус хранится в
`provisioning_jobs`, а не в памяти процесса.

## 4. Что запросить у hoster.by

Отправить на `sales@hoster.by` и `info@hoster.by`:

1. Есть ли API/личный кабинет партнёра для **автоматического** заказа доменов и
   хостинга?
2. Есть ли API регистрации доменов, продления, управления DNS (A, AAAA, CNAME,
   TXT, MX)?
3. Есть ли API создания/приостановки/удаления хостинг-аккаунтов?
4. Возможен ли реселлерский/white-label режим: счета, субаккаунты, брендирование?
5. Есть ли sandbox и документация (OpenAPI/SOAP)?
6. Какие ограничения на автоматические заказы и оплату?
7. Поддерживается ли автоматическое развёртывание Docker/Python-приложений на
   VPS/облаке?
8. Какой хостинг соответствует требованиям Закона № 99-З и приказа ОАЦ № 66 для
   персональных данных? Можно ли разместить multi-tenant SaaS?
9. Есть ли SLA и возможность резервирования?
10. Условия дилерской программы: закупка, маржа, отчётность, договор.

До получения ответов считаем, что API нет.

## 6. Домены и DNS: практические правила

- Проверять домен до оплаты, чтобы не продать занятый.
- Хранить статус: `unknown`, `available`, `taken`, `premium`, `reserved`.
- Для `.by` проверять требования к владельцу (физлицо/ИП/юрлицо).
- Не обещать дату регистрации, пока оператор не подтвердил.
- DNS-записи для сайта:
  - `A` → IP edge;
  - `AAAA` → IPv6, если есть;
  - `CNAME www` → основной хост;
  - `TXT _torgovlia-verify` → подтверждение владения;
  - `TXT` SPF/DKIM — если подключаем почту.
- TTL 300 на время миграции, потом 3600.
- SSL выпускать после успешного DNS; следить за автопродлением.
- При переносе домена — не менять NS, пока не готов новый сайт.

## 7. Ограничения и риски

| Риск | Влияние | Меры |
|---|---|---|
| Нет API | ручной провижининг | очередь задач, чек-листы, SLA, автоматизация позже |
| Задержка регистрации домена | клиент ждёт | статус «на проверке», честные сроки |
| Ограничения `.by` | нельзя оформить на филиал | сбор данных заранее, валидация |
| PD-требования | нельзя размещать ПД на обычном хостинге | PD-хостинг hoster.by, договор, аудит |
| Shared-хостинг не тянет | падения, лимиты | VPS/облако, мониторинг |
| Изменение тарифов | экономика | пересчёт раз в квартал, запас 20% |
| Зависимость от одного провайдера | простой | адаптеры, второй провайдер позже |

## 8. Решение по умолчанию

До ответа hoster.by:

- платформа размещается на **VPS/облаке** (Docker Compose, PostgreSQL, Redis);
- домены и хостинг продаются как **pass-through** с ручным оформлением;
- провижининг сайта внутри платформы — автоматический (subdomain + деплой);
- ispmanager используется только для выделенных экземпляров;
- все внешние шаги оформлены задачами с чек-листом и статусами;
- интерфейс не показывает клиенту «ручной режим» — только статусы.

Это даёт запуск без блокировки на API и позволяет включить полную автоматизацию
без переписывания продукта, когда API появится.
